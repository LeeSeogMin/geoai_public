# lecture 폴더 작성 원칙 (GeoAI 학부 강의교재)

`lecture/`는 `docs/`를 근거로 **학부 입문자용 강의교재**를 만드는 공간이다. `docs/`를 줄이거나 요약하는 곳이 아니라, 같은 내용과 사례를 **더 쉬운 말, 더 직관적인 비유, 더 구체적인 단계 설명**으로 다시 풀어 쓰는 공간이다. 따라서 `lecture/` 원고는 `docs/`보다 설명이 많아져 **분량이 더 길어질 수 있다.**

> ⭐ **독립 배포 원칙 (2026-07-08)**: 완성된 `lecture/` 원고는 학생에게 **단독 배포되는 독립 문서**다. 학생은 `docs/`를 받지 않는다. 따라서 본문·머리말·더 알아보기 어디에도 `docs/` 파일을 언급·참조하지 않으며, "원천", "~를 풀어 쓴 버전" 같은 파생 표현도 쓰지 않는다. `docs/`가 원천이라는 사실은 **집필자용 내부 규칙**일 뿐, 문서 표면에 드러내지 않는다. (`lecture_practice/` 실습 코드 참조는 허용 — 실습파일은 학생과 공유한다.)

## 원천 자료

강의교재는 다음 자료를 근거로 작성한다. `lecture/`는 `docs/`를 더 쉬운 언어와 더 촘촘한 설명으로 다시 풀어 쓴 **입문자용 본문**이므로, 사실·수치·실행 결과는 공유하되 설명 방식과 설명 분량은 별도로 구성한다. 원천 자료에 없는 사실·수치·실행 결과·법령 해석은 임의로 추가하지 않는다.

- `docs/ch{NN}.md`: 기준 내용과 사례, 실측 결과의 원천
- `contents.md`: 장별 학습 목표와 절 구성
- `lecture_practice/chapter{N}/`: 실제 실행 코드와 산출물(`results/*.log`)
- `content/research/`: 검증된 참고 자료
- 각 장의 **보론(심화·선택)**과 **부록(H·E·I 등)**: 집필 시 내용 참고 원천으로만 쓴다. 본문에서 연결하지 않으며, "더 알아보기"는 외부 공식 자료로 연결한다.

## 대상 독자

- 지리·도시·환경·행정·정책·데이터 관련 **학부 입문자**(3-4학년 포함)
- Python·데이터 분석을 조금 접했지만, 공간 데이터·머신러닝·정책 분석 경험은 거의 없는 학습자
- GeoAI 개발자가 되기보다, 공간 기반 정책·서비스를 **이해하고 질문하고 평가**해야 하는 학습자

> `docs/`와 `lecture/`는 상하관계가 아니라 **독자 트랙이 다른 두 서술 방식**이다. `lecture/`는 `docs/`보다 더 쉬운 설명과 더 많은 중간 설명을 제공하는 입문자용 본문이다.

## 작성 방향

- 쉬운 말로 시작하고, 기술 정의보다 **"왜 이 문제가 생기는가"**를 먼저 설명한다.
- 일상 비유를 쓰되, 비유가 개념을 왜곡하지 않게 한 줄 단서를 붙인다.
- 공간 고유 개념(좌표계, 공간 자기상관, MAUP, 공간 교차검증, 3층 모델)은 반드시 비유와 작은 예로 직관화한다.
- 코드는 최소화하고, 코드가 보여주는 **현상과 함정**을 설명한다.
- GeoAI의 정체성(3층 모델, "AI를 언제 쓰지 말아야 하는가")을 학부 눈높이로 일관되게 유지한다.
- 심화 주제는 "더 알아보기"에서 표준·제도·데이터의 **공식 외부 자료 URL**로 연결한다. `docs/`의 심화 논의·보론은 집필 시 참고만 하고 본문에서 언급하지 않으며, 본문은 입문자 흐름으로 완전히 자립해야 한다.
- 각 절에는 수업 질문·토론거리·미니 활동을 포함한다.
- 교수자 메타 문장("학부 수업에서는 이렇게 보면 된다", "이 장은 3시간이 적절하다")은 본문에 쓰지 않는다. 학생이 직접 읽는 교재 문장으로만 쓴다.
- 그림을 새로 그리기 어려운 경우, 검증된 외부 자료의 URL을 직접 제시해 실제 도표·지도·설명 페이지를 보게 한다.
- 가능하면 합성 예시보다 **실제 자료와 실측 로그**를 우선 사용한다. 공개 데이터의 원출처 URL을 함께 적어 현실감을 높인다.
- `lecture/` 원고는 **요약본이 아니라 설명서**여야 한다. 짧게 정리하는 것보다, 입문자가 실제 자료를 보며 따라 이해할 수 있게 **쉽고, 직관적이고, 구체적이고, 자세하게** 설명하는 것을 우선한다.
- 따라서 `lecture/`는 `docs/`보다 분량이 짧아야 할 이유가 없다. 오히려 입문자 설명을 위해 **예시, 비유, 중간 해설, 단계별 독해**가 늘어나며 더 길어질 수 있다.
- 어려운 용어는 넘어가지 않는다. 처음 나오는 용어는 모두 쉬운 말, 비유, 작은 실제 예로 풀어서 설명한다.
- 한 절마다 가능하면 **실제 자료 1개 이상**을 중심에 둔다. 정의만 적지 말고 "이 자료를 지금 보고 있다면 무엇이 보이고, 무엇을 읽어야 하는가"를 서술한다.
- URL을 제시할 때는 링크만 나열하지 않는다. **그 페이지를 보고 있다고 가정하고**, 어디를 봐야 하고 무엇이 중요한지 본문 안에서 같이 설명한다.
- STAC, COG, GeoParquet 같은 추상 개념은 반드시 실제 예시와 묶는다. 예: 실제 STAC Item 하나의 `id`, `datetime`, `assets`를 읽어 가며 설명한다.

## 수업 시간 기준

- 기본 설계 단위는 **1회 3시간 수업**이다.
- 각 장은 우선 3시간 안에 핵심 개념, 사례, 활동, 체크 질문까지 마칠 수 있도록 구성한다.
- 난도가 낮은 장은 2시간 수준으로 압축할 수 있지만, 기본 설계는 3시간을 기준으로 한다.
- 3시간 분량을 채운다는 이유로 내용을 억지로 늘리지 않는다. 시간이 더 필요한 이유는 개념 난도, 활동 시간, 코드 시연 해설 중 어디에 있는지 분명히 한다.
- 따라서 `lecture/chapter{N}.md`는 "핵심 3시간 흐름"을 기본값으로 설계하고, 더 알아보기는 과제·복습·심화 확장 블록으로 둔다.

## 장별 파일 구조

- `lecture/chapter1.md` ~ `lecture/chapter15.md` (패딩 없는 번호)
  - 참고(집필자용): `docs/`는 `ch01`~`ch15`(패딩) 번호, 강의교재는 `chapter{N}`(패딩 없음)이다. 각 장 머리말에는 원천 문서를 적지 않는다. 대신 "이 장의 수치는 `lecture_practice/chapter{N}/` 코드를 실제 실행해 얻은 값"임을 한 줄로 명시한다.
- `lecture/epilogue.md` — 마지막 시간. 장 번호를 붙이지 않는다. 다섯 가지 질문으로 전체를 압축하는 문서이며, **짧은 것이 이 문서의 형식**이다. 실습 코드가 없고 새 수치를 넣지 않는다.
- `lecture/bonus-future-geoai.md` — 선택 읽기 보론(기술 전망). 아래 "보론 파일 원칙" 참조.
- 강의용 그림·도식은 `lecture/assets/`에 둔다.
- 슬라이드 초안이 필요하면 `lecture/slides/`에 둔다.

### 보론 파일 원칙 (2026-08-13 신설)

`lecture/`가 자체 보론 파일을 갖게 되면서 원천 자료 절의 "보론은 본문에서 연결하지 않는다"는 규칙에 단서가 필요해졌다. 정리하면 이렇다.

- **`docs/`의 보론·부록**: 집필 시 내용 참고 원천으로만 쓴다. `lecture/` 본문에서 언급·연결하지 않는다(종전 규칙 유지).
- **`lecture/`의 보론**: 학생에게 함께 배포할 수 있는 **선택 읽기 자료**다. 다만 장 본문(`chapter{N}.md`)이 보론을 전제하고 쓰이지 않아야 한다 — 보론을 읽지 않은 학생도 본문만으로 완결되게 한다. 보론 쪽에서 본문 장을 가리키는 것은 허용하되(예: "10·12장에서 본 과잉"), 본문에서 보론을 필수 선행으로 지정하지 않는다.
- 보론 파일 머리말에 **성격(선택 읽기)과 건너뛰어도 무방함**을 한 줄로 밝힌다.
- 파일명은 `bonus-{주제}.md`로 한다.

## 권장 장 템플릿 (9단계)

1. 오늘의 큰 질문
2. 직관적 비유
3. 핵심 개념 3-5개
4. 원천 장과 실측 로그를 바탕으로 풀어 읽는 실제 사례
5. 코드나 시스템 흐름을 쉬운 그림으로 설명
6. 수업 활동 또는 토론 질문
7. 체크 질문
8. **과제** — 제출 명령과 세 문항 (아래 "과제 절 원칙" 참조)
9. 더 알아보기(표준·제도·데이터의 공식 외부 자료 연결)

> 권장 운영 방식: 위 9단계 중 1~7은 3시간 수업의 본 흐름으로, 8은 수업 뒤 제출 과제, 9는 복습·심화 확장 블록으로 배치한다.

### 과제 절 원칙 (2026-08-13 신설)

- 과제 절은 **손으로 쓰지 않는다.** 대표 실습·확인 지점·3번 문항의 원천은 `scripts/submit.py`의 `ASSIGNMENTS` 하나이며, 장 문서의 과제 절은 거기서 생성한다. 두 곳에 같은 내용을 적어 두면 반드시 어긋난다.
- 과제 형식은 열다섯 장이 모두 같다 — **명령 한 줄 → 자동 생성된 제출 파일의 빈칸 세 개 → 파일 하나 업로드.** 장마다 다른 것은 대표 실습과 3번 문항뿐이다.
- **3번 문항은 언제나 "그래서 무엇을 결정하는가"의 변형으로 쓴다.** 1·2번은 결과를 읽으면 답이 나오지만 3번은 그렇지 않다. 이 책이 반복해 세우는 논지(산출물이 결정을 바꿀 때 값을 한다)를 과제 배점이 뒤집지 않게 하는 장치다.
- 실행 성공 여부를 점수로 두지 않는다. 실패한 실행도 오류 기록과 함께 제출하게 한다.

## 금지 사항

- **본문·머리말·더 알아보기 어디에도 `docs/` 문서를 언급·참조하지 않는다.** 학생에게 배포되는 것은 `lecture/`뿐이며, `docs/`와 `lecture/`는 서로 참조하지 않는 독립 트랙이다.
- 원천 자료에 없는 실행 결과를 "예시 결과"처럼 쓰지 않는다.
- 어려운 내용을 삭제하면서 핵심 위험(편향·낙인·재현성·책임성)까지 없애지 않는다.
- 비유를 위해 법·규제·보안·통계 요구사항을 단순화해 단정하지 않는다.
- `docs/`와 다른 용어를 임의로 만들지 않는다.
- 개념만 얕게 훑는 **요약형 원고**로 끝내지 않는다.
- 실제 자료를 보여 주지 않은 채 추상 정의만 늘어놓지 않는다.
