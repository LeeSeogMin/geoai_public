# GeoAI 실습 시작하기

이 문서 하나만 따라 하면 실습 환경이 준비된다. 위에서부터 순서대로 하고, 막히면 아래 "잘 안 될 때"로 간다.

이 수업은 온라인으로 진행하고, 실습은 각자 자기 컴퓨터에서 혼자 한다. 옆에서 화면을 봐 줄 사람이 없으므로 **혼자서도 막힌 지점을 찾아낼 수 있게** 만들어 두었다. 진단 도구가 무엇이 빠졌는지 문장으로 알려주고, 그 문장을 AI 에이전트에 그대로 붙여넣으면 해결 방법이 나온다.

그래도 안 되면 물어볼 곳이 두 군데 있다.

- **수업 게시판** — 글로 묻는다. 오류 메시지와 진단 파일을 붙여 올리면 된다. 대부분의 문제는 여기서 끝난다.
- **화상 실습상담** — 화면을 함께 보며 푼다. 글로 주고받기 어려운 문제, 설치가 통째로 막힌 경우에 쓴다.

**설치가 안 된다고 수업을 놓치는 일은 없어야 한다.** 혼자 오래 붙잡고 있지 말고 위 두 곳을 쓰자. 언제 어느 쪽으로 갈지는 아래 "그래도 안 될 때"에 정리해 두었다.

실습은 **VS Code + AI 코딩 에이전트**로 진행한다. 코드를 한 줄씩 외워서 치는 수업이 아니라, 하고 싶은 분석을 말로 설명하고 에이전트와 함께 코드를 만들어 돌려 보는 수업이다. 다만 **환경 준비만큼은 직접** 한다. 여기서 무엇이 어디에 깔렸는지 모르면, 나중에 에이전트가 만든 코드가 왜 안 도는지도 알 수 없다.

준비 시간은 처음 한 번에 30분에서 1시간쯤 걸린다. 한 번 해 두면 학기 내내 다시 하지 않는다.

## 0. 내 컴퓨터 확인

| 항목 | 최소 조건 | 비고 |
|---|---|---|
| 운영체제 | Windows 10/11 또는 macOS 12 이상 | 둘 다 지원한다 |
| 저장 공간 | 5GB 이상 여유 | 5-7장 딥러닝까지 하면 더 필요하다 |
| 메모리 | 8GB 이상 | 16GB면 넉넉하다 |
| 인터넷 | 필요 | 실습 데이터를 내려받는다 |

그래픽카드(GPU)는 없어도 된다. 딥러닝 실습은 CPU만으로 돌아가도록 크기를 줄여 두었다.

## 1단계. 프로그램 세 가지 설치

**Python, VS Code, Git** 세 가지를 깐다. 이미 깔려 있으면 건너뛴다.

### Python

**3.12 버전**을 권장한다. 실습 코드를 실제로 돌려 검증한 버전이다.

- Windows: [python.org/downloads](https://www.python.org/downloads/)에서 3.12 설치 파일을 받는다. 설치 화면 맨 아래 **"Add python.exe to PATH"에 반드시 체크**한다. 이걸 놓치면 터미널에서 `python` 명령이 먹지 않는다.
- macOS: [python.org/downloads](https://www.python.org/downloads/)에서 3.12 설치 파일을 받는다. Homebrew를 쓴다면 `brew install python@3.12`도 된다.

설치가 끝나면 터미널(Windows는 PowerShell, macOS는 터미널)에서 확인한다.

```
python --version
```

`Python 3.12.x`가 나오면 성공이다. macOS에서 `python`이 없다고 나오면 `python3 --version`으로 해 본다.

### VS Code

[code.visualstudio.com](https://code.visualstudio.com/)에서 받아 설치한다. 설치 후 왼쪽 확장(Extensions) 탭에서 **Python** 확장을 깐다(Microsoft 제공).

### Git

- Windows: [git-scm.com](https://git-scm.com/download/win)에서 받아 설치한다. 옵션은 모두 기본값으로 둔다.
- macOS: 터미널에서 `git --version`을 치면 없을 경우 설치를 물어본다. 물어보는 대로 설치한다.

## 2단계. 실습 파일 받기

수업 자료가 올라가 있는 저장소 주소는 수업 시간에 공지한다. 받을 위치를 정한 다음(예: 문서 폴더) 터미널에서 아래를 실행한다.

VS Code에서 `File > Open Folder`로 방금 받은 `geoAI` 폴더를 연다. 앞으로 모든 작업은 이 폴더를 연 상태에서 한다.

> **왜 압축파일이 아니라 git인가**: 학기 중에 코드가 고쳐지면 `git pull` 한 줄로 최신본을 받을 수 있다. 압축파일을 다시 받아 덮어쓰면 내가 쓴 코드까지 날아간다.

## 3단계. 가상환경 만들기

가상환경은 **이 수업 전용 파이썬 방 하나를 따로 만드는 것**이다. 수업에서 쓰는 패키지가 컴퓨터 전체 설정을 건드리지 않고, 다른 수업이나 개인 프로젝트와 충돌하지 않는다.

VS Code에서 터미널을 연다(`Ctrl + \`` 또는 `Terminal > New Terminal`). 폴더 위치가 `geoAI`인지 확인하고 아래를 실행한다.

**Windows (PowerShell)**
```
python -m venv .venv
.venv\Scripts\activate
```

**macOS**
```
python3 -m venv .venv
source .venv/bin/activate
```

성공하면 터미널 줄 앞에 `(.venv)`가 붙는다. 이게 붙어 있어야 이 방 안에 있는 것이다. **터미널을 새로 열 때마다 활성화 명령을 다시 쳐야 한다.**

> **Windows에서 "이 시스템에서 스크립트를 실행할 수 없으므로"라는 오류가 날 때**: PowerShell이 스크립트 실행을 막고 있다. 아래를 한 번 실행하고 다시 시도한다.
> ```
> Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
> ```

VS Code 오른쪽 아래(또는 `Ctrl+Shift+P` → `Python: Select Interpreter`)에서 방금 만든 `.venv`를 선택해 둔다. 그래야 편집기가 코드를 제대로 인식한다.

## 4단계. 패키지 설치

`(.venv)`가 붙어 있는 상태에서 실행한다.

```
pip install -r lecture_practice/requirements-student.txt
```

5분에서 15분쯤 걸린다. 1장부터 4장, 8장부터 13장까지 이 설치분으로 진행한다.

딥러닝을 쓰는 **5-7장은 학기 중반에** 추가로 깐다. 용량이 크고, 컴퓨터마다 받아야 할 파일이 달라서 아래 명령 하나로 처리한다.

```
python lecture_practice/setup_torch.py
```

이 명령이 내 컴퓨터를 살펴보고 맞는 것을 골라 깐다.

- NVIDIA 그래픽카드가 있는 Windows/Linux: 그래픽카드용(CUDA) 빌드 — 학습이 몇 배 빨라진다
- 애플 실리콘 맥(M1 이상): 기본 빌드 (맥 내장 GPU를 MPS로 쓴다)
- 그 외: CPU 빌드

설치가 끝나면 실제로 GPU 계산을 한 번 돌려서 정말 되는지까지 확인해 준다. **그래픽카드가 없어도 실습은 모두 할 수 있다.** 시간이 더 걸릴 뿐이다.

무엇을 깔지 미리 보려면 `python lecture_practice/setup_torch.py --dry-run`, 이미 깔린 상태만 보려면 `--check`를 붙인다.

## 5단계. 제대로 됐는지 확인

```
python lecture_practice/check_env.py
```

항목별로 무엇이 준비됐는지 보여준다. 마지막에 "모든 항목 통과"가 나오면 끝이다.

문제가 있으면 무엇을 하면 되는지 문장으로 알려준다. 그 문장을 그대로 AI 에이전트에게 붙여넣고 "내 운영체제에 맞게 해결 방법을 단계로 알려줘"라고 물어보면 된다. 시킨 대로 한 뒤 진단을 다시 돌려 그 항목이 사라졌는지 확인한다.

실행할 때마다 같은 내용이 `lecture_practice/env-report.txt`로도 저장된다. 두세 번 시도해도 같은 문제가 남으면 **이 파일을 게시판 글에 첨부**한다. 내 컴퓨터 상태가 다 들어 있어서, 무엇이 어떻게 안 되는지 따로 설명하지 않아도 된다.

이어서 1장 실습 코드를 한 번 돌려 본다.

```
python lecture_practice/chapter1/code/1-1-geoai-tools-preview.py
```

전 세계 국가 경계 데이터를 내려받아 대륙별 국가 수를 세는 코드다. `전체 국가 수: 177`이 나오면 환경이 완성된 것이다.

## 실습을 어떻게 진행하나

에이전트에게 "숙제 해줘"라고 던지면 코드는 나오지만 배우는 게 없다. 수업에서는 아래 순서를 쓴다.

1. **먼저 말로 정리한다.** 무엇을 알고 싶은지, 어떤 데이터로, 어떤 형태의 답(지도·표·숫자)을 원하는지 한국어로 적는다.
2. **에이전트에게 계획부터 시킨다.** "코드 짜기 전에 어떤 순서로 할지 단계로 먼저 알려줘"라고 요청한다. 계획이 이상하면 여기서 잡는다.
3. **코드를 받아 직접 돌린다.** 에이전트가 대신 돌려 준 결과만 믿지 않는다. 내 터미널에서 실행해 같은 결과가 나오는지 본다.
4. **결과를 의심한다.** 숫자가 나왔다고 맞는 게 아니다. "이 값이 왜 이렇게 나왔는지 설명해줘", "이 분석이 틀릴 수 있는 경우는 뭐야"를 반드시 물어본다.
5. **모르는 용어는 그 자리에서 묻는다.** "좌표계를 왜 바꿔야 해?"처럼 물으면 된다. 이 질문을 미루면 다음 장에서 막힌다.

**하지 말 것**

- 데이터가 없다고 에이전트가 숫자를 지어내게 두지 않는다. 실습 결과는 실제로 돌려서 나온 값만 쓴다.
- 오류 메시지를 지우거나 예외 처리로 덮어서 넘어가지 않는다. 오류는 원인을 찾아 고친다.
- 이해하지 못한 코드를 그대로 제출하지 않는다. 설명하지 못하는 코드는 내 것이 아니다.

### 작업 기록 두 개: context.md 와 todo.md

에이전트는 대화를 새로 시작하면 앞의 내용을 기억하지 못한다. 어제 두 시간 걸려 정한 것도 오늘은 모른다. 그래서 **기억을 파일에 남긴다.** 저장소 루트에 두 개가 있다.

- **`context.md`** — 지금 무엇을 왜 하고 있는지. 목표, 정한 것과 그 이유, 쓰는 데이터, 막힌 것.
- **`todo.md`** — 할 일을 쪼갠 목록. 끝낸 것은 `[x]`로 바꾼다.

쓰는 방법은 간단하다.

1. 세션을 시작할 때: `context.md와 todo.md 읽고 시작해줘. 다음에 할 것 하나만 같이 하자.`
2. 무언가 정했을 때: `방금 정한 걸 context.md에 한 줄로 추가해줘.`
3. 끝냈을 때: `방금 끝낸 항목 todo.md에서 체크해줘.`

**왜 이게 중요한가.** 큰 요청 하나를 통째로 던지면 에이전트는 열 가지 중 서너 개를 빠뜨린다. 할 일을 쪼개 적고 하나씩 시키면 이 문제가 거의 사라진다. 여러 날에 걸친 과제일수록 차이가 커진다.

파일이 길어지면 끝난 것과 옛 맥락을 지운다. 짧고 최신일 때 가장 쓸모 있다.

## 과제는 어떻게 내나

매 장마다 과제가 하나씩 있다. 형식은 열다섯 번 모두 같다. **명령 한 줄을 돌리고, 만들어진 파일에 세 문장을 채워, 그 파일 하나를 올린다.**

### 1) 명령 한 줄

가상환경을 켠 상태에서 저장소 루트에서 돌린다. 아래는 11장 과제를 만드는 예다.

```bash
python scripts/submit.py 11 --id 201912345 --name 홍길동
```

`--id`에는 자기 학번을 적는다. 이 명령이 대신 해 주는 일은 셋이다.

1. **실습에 필요한 데이터를 만든다.** 저장소를 내려받아도 데이터 파일은 들어 있지 않다(용량과 저작권 때문에 뺐다). 이 단계가 그것을 만든다. 그래서 어떤 장을 처음 돌릴 때는 조금 더 걸린다.
2. **그 장의 대표 실습을 돌린다.** 장마다 한 개씩 정해져 있다. 무엇이 돌아가는지 미리 보려면 `--dry-run`을 붙인다.
3. **제출할 파일을 만든다.** 실행 결과가 이미 붙어 있는 상태로 나온다.

### 2) 세 문장 채우기

끝나면 이런 파일이 생긴다.

```
submissions/제출_11장_201912345.md
```

열어 보면 위쪽에 실행 기록과 결과가 이미 들어가 있다. **손댈 곳은 맨 아래 "여기만 채우세요" 뿐이다.**

1. 눈에 띈 숫자 하나를 그대로 옮겨 적고, 왜 눈에 띄었는지
2. 그 숫자가 왜 그렇게 나왔는가
3. 그래서 무엇을 결정하겠는가 (질문은 장마다 다르다)

**3번이 점수의 대부분이다.** 1·2번은 결과를 들여다보면 답이 나오지만 3번은 그렇지 않다. 에이전트가 대신 해 줄 수 없는 것도 3번이다.

### 3) 파일 하나 올리기

채운 그 파일만 수업 게시판에 올린다. 폴더를 압축할 필요도, 여러 개를 올릴 필요도 없다.

### 알아 둘 것

- **실행이 실패해도 제출한다.** 오류 메시지가 그 파일에 자동으로 담기고, 질문이 "어디서 막혔나"로 바뀐다. 어디서 왜 막혔는지 적은 제출도 온전한 제출이다. **실행 성공 여부로 점수를 매기지 않는다.**
- **숫자는 학번마다 다르다.** 난수를 학번에서 계산하기 때문이다. 옆 사람과 값이 다른 것이 정상이고, 남의 파일을 그대로 내면 바로 드러난다. 다만 난수를 쓰지 않는 장(1·3·12·14장)은 모두 같은 값이 나오는 것이 정상이며, 그 장의 제출 파일에 그렇게 적혀 있다.
- **다시 돌려도 내 숫자는 그대로다.** 학번이 같으면 몇 번을 돌리든 같은 값이 나온다.
- **오래 걸리지 않는다.** 대부분의 장이 1분 안에 끝난다. 가장 오래 걸리는 장도 2분 남짓이다.
- 만들어진 `submissions/` 폴더는 각자의 컴퓨터에만 남는다. 저장소에 올라가지 않는다.

## Windows와 macOS 차이

실습 코드는 양쪽에서 똑같이 돌아가도록 만들었다. 다만 아래 세 가지는 운영체제마다 다르다.

### 1) 명령어 차이

| 하는 일 | Windows | macOS |
|---|---|---|
| 가상환경 활성화 | `.venv\Scripts\activate` | `source .venv/bin/activate` |
| 파이썬 실행 | `python` | `python3` (또는 `python`) |
| 경로 구분자 | `\` | `/` |

문서에 나오는 경로는 `/`로 적었다. Windows에서도 파이썬 코드 안에서는 `/`가 그대로 동작하므로 바꿀 필요가 없다.

### 2) Windows 한글 인코딩

Windows 한국어 환경은 기본 문자 인코딩이 `cp949`다. 실행 결과를 화면에 띄울 때는 문제가 없지만, **결과를 파일로 저장하거나 다른 프로그램으로 넘길 때** 한글과 특수기호(→, —)가 깨지거나 오류가 난다.

해결은 환경변수 하나를 켜는 것이다. VS Code에서 `geoAI` 폴더 안에 `.vscode/settings.json` 파일을 만들고 아래를 넣는다.

```json
{
  "terminal.integrated.env.windows": { "PYTHONUTF8": "1" },
  "terminal.integrated.env.osx": { "PYTHONUTF8": "1" }
}
```

VS Code 터미널을 닫았다 다시 열고 `python lecture_practice/check_env.py`를 실행하면 "2. 문자 인코딩" 항목에서 확인할 수 있다.

### 3) 한글 폰트

그림에 한글이 들어가면 폰트가 필요하다. Windows는 맑은 고딕, macOS는 애플고딕이 기본으로 있어 대개 그냥 된다. 그림의 한글이 네모(□□□)로 나오면 [나눔고딕](https://hangeul.naver.com/font)을 설치하고 VS Code를 다시 켠다.

## 잘 안 될 때

| 증상 | 원인과 해결 |
|---|---|
| `python: command not found` | Windows: Python 설치 때 "Add to PATH"를 놓쳤다. Python을 지우고 그 항목에 체크해 다시 설치한다. macOS: `python3`로 쳐 본다. |
| `pip install`이 중간에 멈추거나 실패 | 인터넷 문제이거나 학교 방화벽이 막는 경우가 많다. 다른 네트워크에서 다시 시도한다. 그래도 안 되면 오류 메시지 전체를 에이전트에게 붙여넣는다. |
| `ModuleNotFoundError: No module named 'geopandas'` | 가상환경이 꺼져 있다. 터미널 앞에 `(.venv)`가 있는지 보고, 없으면 3단계의 활성화 명령을 다시 친다. |
| 활성화했는데도 같은 오류 | VS Code가 다른 파이썬을 보고 있다. `Ctrl+Shift+P` → `Python: Select Interpreter`에서 `.venv`를 고른다. |
| `UnicodeEncodeError` / 결과 파일의 한글이 깨짐 | 위 "Windows 한글 인코딩"을 적용한다. |
| 그림의 한글이 네모로 나옴 | 위 "한글 폰트"를 적용한다. |
| 데이터 파일이 없다는 메시지 | 각 장 폴더의 `-0-`으로 시작하는 데이터 준비 코드를 먼저 돌린다. 메시지에 어느 파일을 돌리라고 나온다. |
| 그래픽카드가 있는데 학습이 느림 | CPU 빌드가 깔린 것이다. `python lecture_practice/setup_torch.py`를 실행하면 맞는 빌드로 바꿔 준다. `python lecture_practice/check_env.py`의 "딥러닝 장치" 항목에서 지금 무엇으로 도는지 볼 수 있다. |
| `CUDA error` / GPU 연산에서 오류 | 그래픽카드가 너무 오래됐거나 드라이버가 낮다. `python lecture_practice/setup_torch.py`가 이 경우를 감지해 CPU 빌드로 바꾸는 명령을 알려준다. CPU로도 실습은 모두 된다. |

### 그래도 안 될 때 — 어디까지 혼자 하고, 언제 물어보나

온라인 수업이라 옆에서 봐 줄 사람이 없다. 대신 아래 순서가 그 자리를 대신한다. **위에서부터 차례로** 간다.

**1단계. 에이전트에게 통째로 넘긴다 (바로)**
오류 메시지를 요약하지 말고 **전체를 그대로** 붙여넣는다. "내 운영체제는 (윈도우/맥)이고, 방금 이걸 하려던 참이었어"를 덧붙인다. 요약하면 진짜 원인이 잘려 나간다.

**2단계. 한 번에 하나만 고친다**
에이전트가 방법을 여러 개 주면 위에서부터 하나씩 해 보고, 매번 `python lecture_practice/check_env.py`로 확인한다. 한꺼번에 바꾸면 무엇이 통했는지 알 수 없어서 다음에 또 막힌다.

**3단계. 되돌린다**
설치가 꼬였다 싶으면 `.venv` 폴더를 통째로 지우고 3단계부터 다시 한다. 실습 코드는 그대로 있으니 잃는 것이 없다. 이 방법이 가장 빠를 때가 많다.

**4단계. 게시판에 묻는다 (같은 곳에서 30분 넘게 막혔을 때)**
혼자 더 붙잡는다고 풀리지 않는다. 아래를 갖춰 올리면 답이 빨리 온다.

- 제목: 증상 한 줄 (예: `4단계 pip install에서 rasterio 설치 실패 (윈도우 11)`)
- 운영체제와 파이썬 버전
- **오류 메시지 전체** (줄여서 옮기지 않는다)
- 1~3단계에서 시도한 것과 그 결과
- 첨부: `lecture_practice/env-report.txt`

에이전트가 알려준 방법을 그대로 적어 주면 더 좋다. 무엇이 안 통했는지가 단서가 된다.

**5단계. 화상 실습상담을 신청한다**
아래에 해당하면 글로 주고받기보다 화면을 함께 보는 편이 빠르다.

- 게시판 답변대로 했는데도 같은 곳에서 막힌다
- 설치가 통째로 진행되지 않아 무엇부터 봐야 할지 모르겠다
- 오류 메시지 없이 그냥 안 된다 (붙여넣을 것이 없는 경우)

신청 전에 `python lecture_practice/check_env.py`를 한 번 돌려 두고, 상담 때 그 화면과 문제가 나는 상황을 바로 보여줄 수 있게 준비한다. 준비돼 있으면 상담 시간이 훨씬 짧아진다.

### 최후 수단: 구글 코랩

노트북이 너무 느리거나 설치가 끝내 안 되면 [Google Colab](https://colab.research.google.com/)에서 진행할 수 있다. 브라우저만 있으면 되고 설치가 필요 없다. 다만 코랩에서는 VS Code의 AI 에이전트를 그대로 쓰기 어려워 이 수업이 연습하려는 작업 방식과 멀어진다. 임시로 진도를 따라가는 용도로 쓰되, 게시판에 상황을 알리고 화상 실습상담으로 로컬 설치를 마무리하는 편이 좋다.

## 폴더가 어떻게 생겼나

```
geoAI/
├── AGENTS.md                 에이전트 규칙 (install.py가 만든다)
├── CLAUDE.md                 위 파일을 Claude Code가 읽도록 연결
├── context.md                내 작업 맥락 (직접 쓴다)
├── todo.md                   내 할 일 목록 (직접 쓴다)
├── lecture/                  강의 교재 (chapter1.md ~ chapter14.md)
└── lecture_practice/                 실습
    ├── README.md             이 문서
    ├── check_env.py          환경 자가진단
    ├── setup_torch.py        내 컴퓨터에 맞는 PyTorch 설치 (5-7장)
    ├── AGENTS.md             에이전트 규칙 원본
    ├── agent-setup/          규칙 파일 배치 도구
    ├── requirements-student.txt      1-4장, 8-13장 패키지
    ├── requirements-student-dl.txt   5-7장 딥러닝 패키지
    └── chapter1/ ~ chapter14/
        ├── code/             실행할 코드 ({장}-{절}-{주제}.py)
        ├── data/             실습 데이터 (준비 코드가 만들어 넣는다)
        └── results/          실행 결과 (로그·표·그림)
```

코드 파일 이름 규칙은 이렇다.

- `4-0-...` : **0번은 데이터 준비**다. 그 장을 시작할 때 가장 먼저 돌린다.
- `4-1-`, `4-2-` : 교재 절 번호와 맞는 분석 코드다. 번호 순서대로 돌린다.
